# Handmade Store - обзор на проекта

## Какво представлява проектът

Проектът тръгна като лична онлайн магазин за хендмейд продукти, но вече е архитектуриран като **multi-vendor marketplace** - платформа тип Etsy за българския пазар, където различни производители (vendors) могат да качват и продават собствени продукти, не само аз. Това не е просто идея на хартия: всеки `Product` вече задължително сочи към `vendor` (конкретен `User`), а `User` модела има `vendorStatus` enum (`none` / `pending` / `approved` / `suspended`), което е точно механизмът за одобряване на нови продавачи. Основата за marketplace е заложена правилно от самото начало, не е прилепена като хрумване по-късно.

## Технологичен стек

**Backend** (`handmade-backend/`): Node.js (ESM), Express 5, MongoDB + Mongoose 9, JWT в httpOnly cookie за автентикация, bcrypt за пароли.

**Frontend** (`handmade-store/`): React 19 + Vite, React Router 7, Context API за глобален state (auth, количка, wishlist, quick view), Vitest + Testing Library за тестове, react-bootstrap + Font Awesome за UI.

Монорепо структура - `handmade-backend/` и `handmade-store/` като два независими package.json под общ root.

## Какво реално работи към момента

Потребителският интерфейс е в добро състояние: каталог с продукти, филтриране по категория/таг/цена/сортиране, търсене, страница с детайли на продукт, quick view модал, "продукт на деня" и други секции на началната страница, wishlist. Количката има собствен `ShopContext`.

Автентикацията е завършена и солидна: регистрация, логин, JWT в httpOnly cookie, проверка на сесия през `/users/me` при зареждане, `ProtectedRoute`/`PublicOnlyRoute` guard-ове, разделени роли (`role`) и vendor статус (`vendorStatus`).

Профилната зона (`/account/profile`) има скелет с табове - Dashboard, Orders, Address, Account Details. От тях реално докрай работи само адресите (списък + добавяне, с валидация за максимум 2 адреса); останалите три таба са UI обвивки без завършена backend връзка.

Споделен API слой (`apiClient`, `useQuery`, `useMutation`) е изграден правилно, с unit тестове за ключовите hooks.

## Най-голямата дупка спрямо визията: липсва vendor слой

Базата данни е готова за marketplace, но **няма нито един ред UI или route за продавач**. Няма форма "стани продавач", няма admin екран за одобряване на `vendorStatus`, няма dashboard за vendor да качва/редактира собствени продукти, няма backend route-ове за това (`routes.js` в момента товари само `productController` и `userController` - няма `vendorController`). Това е разликата между "каталог, който аз пълня ръчно" и "платформа, в която трети страни продават".

## Най-спешен блокер: checkout изобщо не работи

Дори и в еднопродавачев режим, в момента **не може да се завърши поръчка**:

- `models/Order.js` не може дори да се import-не - липсва `import mongoose` (моделът ползва `mongoose.model(...)`, но е импортирал само `Schema`), а и `arrayLimit` validator-ът никъде не е дефиниран.
- Няма `POST /orders` endpoint на backend-а.
- Няма checkout страница на frontend-а (количка → адрес → поръчка).
- Orders табът в профила рендва празно, защото `Profile.jsx` изобщо няма заявка за него.

Това е критичният път до работещ MVP - без него магазинът визуално работи, но никой не може реално да купи нищо.

## Други забележими бъгове (пълният списък е в двата README файла)

Logout не прави истински logout - само чисти local state, httpOnly куката остава и сесията се възстановява при следващ reload. Търсенето гърми на специални символи в заявката (`(` връща 500, риск от ReDoS). Seed скриптът на backend-а е чупен (пречи на лесен local setup). Edit формата за адрес се отваря празна и праща `PATCH` заявка към несъществуващ route.

## Препоръчан приоритет напред

1. **Оправи `Order.js` + implement-ни `POST /orders` + свържи checkout flow.** Това е сърцето на всеки e-commerce продукт - без него нищо друго няма значение функционално.
2. **Оправи logout бъга** - в момента е и UX, и security проблем (сесията не се прекратява реално).
3. **Реши дали строиш vendor слоя сега или по-късно.** Ако платформата наистина е замислена като marketplace, това е стратегическата фийча, не "nice to have" - означава нов `vendorController`, нов route group, UI за кандидатстване и admin одобрение.
4. Довърши останалите account табове (Account Details форма, реални Orders данни) и адрес edit/delete flow-а.
5. Мини през refactoring/bug списъците в `handmade-backend/README.md` и `handmade-store/README.md` - те са добре поддържани и достатъчно детайлни, не ги дублирам тук.
